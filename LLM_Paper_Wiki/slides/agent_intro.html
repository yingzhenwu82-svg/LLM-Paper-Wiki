LLM Agent
從工具使用到反思學習

理解 Agent 如何推理、使用工具、接收回饋並累積能力。

本簡報由本 Wiki 初始筆記編譯；正式引用前請核對原文。

01｜什麼是 LLM Agent？

Agent 不只是一次生成文字。它可以在任務中選擇行動、使用工具、接收環境回應，並根據結果繼續下一步。

LLM

規劃、理解、決策

Tools

搜尋、程式、API 等

Environment

任務與回應

02｜Agent 的基本循環

理解→決定行動→執行工具→觀察結果→下一步／停止

觀察回傳結果後，Agent 可以更新策略；如果結果不符合預期，可能需要重試或修正。

03｜ReAct：推理與行動交替

ReAct 以 Thought、Action、Observation 的交替方式，把思考與環境行動連結起來。

Thought→Action→Observation↺

觀察提供 grounding，讓後續決策依據實際回應，而非只靠原先生成。

來源：Yao et al., ReAct (2022) — arXiv

04｜Toolformer：模型學會使用工具

Toolformer 探索如何讓模型從資料與自我監督流程學習何時插入 API 呼叫，而不是完全依靠人工逐次示範。

  • 工具可補足模型外部能力。
  • 模型學習選擇性地呼叫工具。
  • 工具呼叫是否有用，需以任務與評估方式驗證。

來源：Schick et al., Toolformer (2023) — arXiv

05｜Reflexion：從回饋中反思

Reflexion 利用語言反思與 episodic memory，讓 Agent 在後續嘗試中參考過去的回饋。

Attempt→Feedback→Reflection→Memory↺

反思本身也可能出錯；重要的是回饋品質與實際驗證。

來源：Shinn et al., Reflexion (2023) — arXiv

06｜Voyager：開放式探索與技能累積

Voyager 在 Minecraft 探索環境中，使用自動課程、回饋循環與技能庫等設計，逐步探索並保存可重用技能。

  • 探索與課程安排
  • 執行後取得回饋
  • 將技能保存並重用

來源：Wang et al., Voyager (2023) — arXiv

07｜SWE-agent：工具介面也很重要

SWE-agent 研究 Agent-Computer Interface，讓 Agent 在軟體工程環境中操作檔案、程式與相關工具，處理軟體問題。

Agent 的表現不只取決於模型，也可能受到工具介面與互動設計影響。

來源：Yang et al., SWE-agent (2024) — arXiv

09｜設計 Agent 時的提醒

  • 明確定義任務、工具與停止條件。
  • 檢查工具輸入與回傳結果。
  • 對高風險操作加入權限與確認。
  • 保留可追溯來源，避免將推論當成論文事實。
  • 回饋與反思需經評估，不保證自動改善。
